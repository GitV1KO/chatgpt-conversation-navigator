# 1.0.1：用户 Brave 中的真实测试

日期：2026 年 10 月 28 日。环境为用户已经打开、已登录 ChatGPT 的日常 Brave 窗口；Brave 应用版本 `152.1.94.119`（从本机应用 Info.plist 读取）。通过原生浏览器界面操作和开发者工具 Elements 面板核查 DOM，没有使用模拟 ChatGPT 页面、替代会话或测试账号。

本次没有发送、编辑或删除聊天消息，没有读取 Cookie、Token、隐藏应用状态或内部会话接口。安装好的扩展直接加载项目 `extension/` 目录，已在扩展管理页重新加载为 **1.0.1** 并刷新真实聊天。

## 确认的原因和修复

1. **新版消息结构不匹配**：原来依赖的 `data-message-author-role` / `data-turn` 在故障页面中不存在。真实页面使用 `data-chatgpt-search-unit-key="…:user"`、`data-chatgpt-search-message-ids` 和旁边的 `data-conversation-role="user"` 标题。已按正文单元识别并使用真实 UUID 去重。
2. **SPA 保留隐藏旧页面**：切换会话时，旧页面仍留在 `data-app-shell-active-page="false"` 的子树中，旧版会误选第一个隐藏对话根节点。已按当前会话 UUID、活动状态和实际布局选择正确根节点，并观察活动状态变化。
3. **虚拟列表需要逐段扫描**：直接跳到顶部会漏掉中间只在经过时才挂载的用户消息。已改为有重叠的逐视口扫描，显示新增数量、限制次数和时长，并支持继续、停止和阅读位置恢复。
4. **节点卸载与高度变化**：记录稳定回合 key 和位置提示，离屏目标先恢复原文，再校验身份、全文与位置。跳转和恢复后进行有界重测，避免过早报告成功。

## 已观察到的真实结果

公开版本已将会话标题和实际搜索内容脱敏；保留测试步骤、数量与验证边界。

| 操作 | 实际结果 |
| --- | --- |
| 重载会话 A | 目录由故障时的 0 条变为 5 条实际挂载的用户提问 |
| 搜索中文关键词 | 找到 1 条，文字匹配高亮；点击后页面显示对应蓝色用户提问，目录选中并提示已定位 |
| 会话 B 目录 | 识别出 5 条当前挂载的真实用户提问，包含图片附件占位 |
| 英文大小写搜索 | 用大写关键词匹配原文中的小写内容，找到 1 条；点击后真实页面滚动至带图片的对应提问，并可见临时高亮边框 |
| 不刷新页面切换会话 | 通过 ChatGPT 左侧会话链接切换，旧搜索词清空；内容就绪后目录替换为新会话，排除隐藏的旧容器 |
| 第一轮主动扫描 | 会话 A 的目录从 5 条增至 25 条，新增 20 条较早的用户提问；达到单次上限时明确提示可以继续 |
| 最终长回合扫描优化 | 最终源代码重载后，目录从 5 条增至 **45 条**，新增 **40 条**，读到当前页面提供的顶部；截图目视确认原目标提问仍位于恢复后的阅读位置 |
| 停止扫描 | 点击加载后按 Esc，面板收起；重新展开可见“已停止加载，已恢复阅读位置”提示 |
| 代码问题搜索 | 搜索代码关键词 找到对应代码提问，点击后实际页面显示同一提问 |
| 离屏原文恢复 | 点击标记“原文暂不在页面中”的已缓存提问，扩展恢复原文，实际页面显示该用户提问，目录提示已定位 |
| 高度重算后的恢复 | 在最近的目标问题处发起扫描，结束后目视核对页面回到同一问题；无法精确核对时实现会改为提示“尽量恢复” |
| 页面刷新 | 修复后的扩展可重新注入，识别当前挂载消息；内存索引按设计重建 |
| 两个已打开的真实标签页 | 原先的另一个会话 B 标签页也已刷新并出现 5 条当前提问；返回会话 A 标签页时 45 条内存目录仍在 |

第一轮发现问题后仍修改了阅读位置恢复、对齐、活动根节点和长回合扫描逻辑，随后在同一 Brave 中重载并再次验证相关操作。最终目录达到 45 条的结果来自最后一次源代码重载后的实测。本次没有用历史的“28/28 模拟测试”代替这些实测；历史报告仅用于保留上一版开发记录。结构化记录及源文件校验值见 [live-brave-1.0.1.json](../tests/results/live-brave-1.0.1.json)。

## 可重复操作和边界

打开右侧目录后，可直接搜索已经索引的提问并点击定位。需要更早历史时点击“加载更早消息”，观察新增数量；单次最多 120 步或约 30 秒，未扫描完可再次点击继续。到顶部时在剩余预算内最多等待 8 秒，网页未返回更多历史会明确报告新增为 0 和目录可能不完整。

真实测试中也观察到某次扫描到顶部后新增为 0：网页没有在该轮提供更多节点。这个结果没有被当成“完整历史已取回”；随后按已缓存身份恢复离屏问题时，网页又挂载了更多回合，目录继续增长。历史加载仍受网页自身懒加载、网络和虚拟化策略影响，不能保证一次获得服务器端全部历史。

以下内容本次未验证：真实发送新消息后的更新、编辑/分支操作、Chrome 本机、其他账号实验布局、浅色主题、浏览器原生缩放及数小时持续内存表现。没有为了测试向账号发送内容。用户初始截图中的零索引、现有问题搜索和实际定位已在其真实会话中复现并修复。
