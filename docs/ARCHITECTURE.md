# 实现原理与维护说明

本扩展只读取页面公开渲染的 DOM，维护当前会话的用户消息目录。网页没有渲染过的消息不在目录中；“已索引”不是服务器上的消息总数。所有聊天文本、搜索词和索引保存在当前标签页的内存中。

## 模块边界

| 文件 | 责任 |
| --- | --- |
| `extension/manifest.json` | Manifest V3 配置，限定 ChatGPT 的两个域名、顶层页面和隔离执行环境 |
| `extension/src/dom.js` | 语义消息识别、纯文本提取、稳定标识、滚动容器及可视区域判断 |
| `extension/src/index.js` | 消息记录、已加载节点绑定、顺序维护、可定位性检查 |
| `extension/src/navigation.js` | 点击定位、结果验证、短暂高亮、用户主动触发的历史加载与取消 |
| `extension/src/panel.js` | Shadow DOM 面板、搜索、摘要、匹配高亮、主题及响应式显示 |
| `extension/src/content.js` | 页面生命周期、增量观察、路由切换、模块协作及资源清理 |

脚本按清单顺序加载，通过隔离世界中的 `globalThis.CGN` 共享模块。没有后台服务、运行时包下载、远程脚本或构建时框架依赖。

## 消息识别

1.0.1 的真实网页适配补充：当前 ChatGPT 使用 `data-chatgpt-search-unit-key="…:user"` 标记用户消息，嵌套的 `data-content-search-unit-key` 只作为同一单元的包装层；`data-conversation-role="user"` 是消息旁的辅助标题，不能当作问题正文。身份优先采用 `data-chatgpt-search-message-ids` 中的 UUID，其次采用 `data-turn-key` 加用户单元序号。`fallback-turn-N` 没有被当作可靠的永久顺序编号。

当前页面会同时保留多个会话：旧页位于 `data-app-shell-active-page="false"` 的隐藏容器中。对话根节点必须选择当前 URL 对应 UUID 的、处于活动页面且可布局的 `data-thread-find-target="conversation"`，不能直接采用第一个 `main` 或第一个对话容器。

为兼容旧版布局，也识别 `data-message-author-role="user"` 和 `data-turn="user"`。降级路径只接受 `article` / `role="article"` 上明确表达用户发言的语义标签，例如 `You said:`、`你说：`。如果网页删掉所有已知语义属性，扩展宁可显示识别失败，也不会根据文本内容猜测哪些回答是用户问题。

识别范围限制在 `main` / `role="main"` 中，排除助手节点、输入表单、对话框、侧边导航和标记为隐藏的祖先。多个候选包装层规范化为用户消息节点，避免一个问题重复入目录。适配网页变化时，应先更新 `dom.js` 并补充测试，避免在界面模块散布新的站点选择器。

文本提取遍历文本节点，保留代码、表格和块级内容的合理分隔，跳过脚本、编辑区及复制按钮等控件。图片使用图片说明或图片消息占位；无法读到正文的附件使用非文本消息占位，不读取图片文件、附件内容或隐藏应用状态。

## 身份、顺序和虚拟列表

稳定身份优先使用 `data-message-id`，其次是 `conversation-turn-N` 的回合编号或消息所在容器的 DOM 标识。相同文字的两条消息仍可能是两个独立问题，不能用内容摘要或内容哈希替代消息身份。

目录按实际可观察的 DOM 顺序合并；有可靠回合编号时，编号也可辅助插入离屏记录。已经识别但随后被虚拟列表移出的消息保留纯文本记录，并标记原文暂不在页面中；断开的 DOM 子树不长期保存在索引里。

没有稳定标识、又没有与已知消息重叠的 DOM 窗口时，网页并未提供足以证明身份和相对顺序的信息。扩展必须保留这一不确定性，不能把内容相同的消息直接合并，也不能宣称已恢复整段历史的绝对顺序。

每次跳转前后都重新验证节点属于当前用户消息、仍连接在文档中，并且身份与文字符合索引。这样可以避免虚拟列表复用同一 DOM 节点后跳到另一个问题。

## SPA 路由与生命周期

内容脚本处于 Chrome 的 `ISOLATED` 世界。它能读取页面 DOM，但不会读取页面 JavaScript 变量，也不向网页主世界注入代码。路由检测组合使用 `popstate`、`hashchange`、DOM 变更时的路径比较以及低频路径检查。

会话切换时取消正在执行的定位、清空上一会话目录及搜索状态。网页可能先改 URL 再替换 DOM，因此需要暂时隔离上一会话的已知节点；也可能先完成 DOM 更新才触发观察回调，因此不能把“检测到路由变化时看到的所有节点”一概当成旧会话。首次发言使新会话 URL 变成 `/c/...` 时，还需要区分同一内容的地址升级和真正的会话切换。

初始化时保存一个应用实例。开发时重复注入会先销毁旧实例，解除观察器、事件、定时器与高亮；页面离开时也释放资源。

## 增量更新与性能

MutationObserver 收集受影响的子树，通过短延迟合并处理。用户消息变更可以局部识别；助手回复的文本流无需重新构建问题目录。页面主区域被替换、路由改变、用户主动重新识别等情况下，才进行完整扫描。

目录行按消息 ID 复用，搜索和可用性变化不会无条件重建整个面板。面板滚动与聊天滚动分离。没有滚动事件驱动的全页扫描，也不会为了初始建立索引自动滚动聊天内容。

性能测试应同时覆盖大量用户消息和大量助手流式变更：前者检验索引合并与目录渲染，后者检验观察回调是否有效过滤无关变化。

## 定位和历史加载

普通目录点击只定位已加载的准确目标，优先沿目标的实际滚动祖先滚动，并在动画后确认目标进入可视区域。成功后再更新选中状态及短暂高亮；验证失败时显示失败原因，不改为点击附近问题。

历史加载只在用户点击相应按钮后开始，采用有次数上限的页面滚动尝试。它不能调用未公开会话 API，也无法保证页面一定会提供更早消息。加载期间可停止；用户滚轮、触摸或操作页面时也取消，以免与正常阅读争抢滚动。加载结果明确报告新增数量与未找到目标的情况。

1.0.1 改为有重叠的逐视口向上扫描，最多 120 步或约 30 秒；中断位置仅在内存保存，再次主动加载可继续。已经缓存的消息使用回合占位节点和位置提示恢复原文，定位后重测几何位置，避免网页重新计算虚拟回合高度导致“显示成功但位置偏移”。阅读位置也以稳定回合和相对偏移恢复；不能确认精确恢复时明确告知。

如果页面没有提供需要的历史，用户可以手动滚动让页面加载更多消息，再使用目录。面板始终显示已识别数量，不能把“滚到了顶部”直接视为“已获取完整历史”。

## 隐私与界面安全

- 不需要 API Key、Cookie、Token、`tabs`、`storage` 或网络请求权限。
- 不读取 Cookie、认证信息、站点存储、浏览器历史或其他标签页。
- 不持久化聊天文本，不把消息发送到第三方。
- 用户文本始终通过文本节点、`textContent` 和 `mark` 节点显示，不插入动态 HTML。
- Shadow DOM 隔离界面样式；浮层避开输入区，支持主题和缩小窗口。

这些是本扩展的实现约束；网页自身的网络请求与存储行为不由扩展控制。

## 兼容性与测试边界

ChatGPT 没有为本扩展提供受版本保证的消息 DOM API，因此未来网页更新仍可能需要调整适配器。测试页面可以覆盖已知结构、SPA 时序、动态追加、虚拟节点复用、无标识降级、长消息、搜索和滚动验证；它不能证明未来真实网页结构永远兼容。

发布前应同时检查真实登录会话、Chrome / Brave 的实际扩展加载、历史增量加载、长对话与网页主题。测试报告必须区分模拟页面测试、浏览器原生扩展加载测试和真实 ChatGPT 登录会话测试。
